# 战斗初始化
主界面开战检查读取当前配置及data/equipment.json中的装备定义，POST /api/battle/initialize。
角色1到4依次处理，每人武器、防具、饰品1、饰品2；本阶段不处理魔石开战效果。
关闭参战的角色不释放也不接收增幅。关闭的开战特效不执行。
每件装备以佩戴者当时的力量、魔力、技巧、速度乘相应系数求和，增至指定属性。
队伍增幅以施放者当时属性计算一次，同一个增量应用给各参战队友；此前队友的增幅会影响后续装备计算。
单个队友效果需要指定目标，当前界面未提供目标选择；遇到此配置明确报错，不猜测目标。
每个buff单独保存来源角色、装备ID、名称、槽位、目标属性、实际增量、计算用属性快照；永久开战buff持续时间为null。
基础面板与装备定义不修改。所有buff单独记录，不合并来源；最终属性保留在共享角色状态。
攻击增幅辅助函数attack_snapshot只操作一次行动副本，同一特效的多个转化行使用相同来源快照，不同特效依次处理。概率抽取和攻击伤害尚未接入。
已损失血量攻击增幅需要明确最大及当前血量，暂不猜测角色血量公式。
验证：python tests/verify_battle_start.py。

持续buff管理：engine/runtime/buffs.py中的apply_named_buff按目标角色及名称覆盖，不区分来源施法者。先扣除旧记录增量，再读取当前来源属性，单层增量乘新层数；达到上限仍刷新持续时间和数值。expire_buffs在到期时扣回记录增量，同一时刻先过期再处理新行动。一次多目标buff先统一移除旧增量再计算同一来源快照。尚待攻击/回复技能事件调用此基础模块。

冷却：首次行动在1.5秒，后续间隔1.5+技能冷却+floor(max(力量-卸负,1)/(速度+1)*10)/10。只对力速比向下取0.1，固定冷却不重复叠加。计算读取释放技能并结算持续buff后的属性；当前实现将冷却固定为释放时计算值，后续属性变化不追溯重排，待游戏规则确认。

伤害前六乘区：engine/runtime/damage.py读取攻击瞬间属性计算技能系数之和；面板物魔伤、辉印、暴伤增加按百分数除100。暴击率=技能%+面板%+技巧/20%，随机概率限制0到1，暴击乘区1.5+暴伤增加/100，未暴击为1。匹配种族时乘1+特攻倍率；易伤为目标已填写的乘数。返回减伤前伤害及每个乘区和暴击判定明细；护甲与物魔减伤未接入，回复技能另行处理。暴伤增加默认0%，基础1.5由公式提供。

护甲公式修正：伤害乘数=50/(目标护甲-攻击瞬间无视护甲+50)，150护甲及50无视护甲时为1/3，有效护甲0时为1。最后再乘(1-对应物理或魔法减伤百分数/100)。分母非正的情况需确认负护甲规则，当前明确报错。

有效护甲下限规则已确认：max(目标护甲-无视护甲,0)。护甲乘数为50/(有效护甲+50)，最大1；无视护甲超过目标护甲时不额外增伤，取代此前负护甲待确认说明。

生命值与献祭：装备增幅结束后，最大生命值=当前体质×10，开战满血。契约仅允许一个角色开启；参战契约持有人选择旧日支配者-魔及群体献祭后，给全体参战角色各上一个负面buff，t=0不扣血，t=1首次扣最大生命值5%，之后每秒扣同样比例。当前血量同步到攻击属性hitPoint，已损失血量增幅可读取共享状态。实际事件时间线仍待接入。

旧日支配者-魔：14秒首次触发，之后每14秒一次。伤害=当前参战队伍持续魔力总和×技能倍率×(1+佩戴者魔法伤害/100)×(1+佩戴者辉印魔伤/100)×目标魔法易伤×(1-目标魔法减伤/100)。不经过护甲、暴击、种族乘区或攻击瞬时增幅。resolve_contract_tick供时间线在准确触发时间调用，扣除目标当前血量并记录各乘区及累计伤害；完整时间线尚未接入。

契约计时修正：从0.1秒开始，14.1秒首次触发，随后28.1、42.1等。契约佩戴者行动与契约同刻时，暂按实测近似模型以50%决定行动先/契约先，按执行时的持续魔力计算并记录随机值和顺序。resolve_contract_action_tie供后续时间线处理此边界；不将不同时间事件或所有buff到期边界一概随机化。
