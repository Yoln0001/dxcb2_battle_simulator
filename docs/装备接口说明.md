# 自定义装备

运行根目录server.py，页面工具栏点击“装备库”，创建并保存装备。
装备保存至data/equipment.json，与技能库分开。双击HTML则保存到当前浏览器。
支持搜索、编辑、副本、查看数据、导入及导出。迁移到其他浏览器前请导出备份。

类型：武器、防具、饰品、魔石。武器职业只选六大类（圣职、战士、法师、潜行者、火枪手、野蛮人），对应大类下各转职共用武器；其他类型会清空此项。
基本信息：类型、装备名称、武器职业。
战斗开始增幅：战斗开始特效名称、开始buff对象、四项开战系数与转化目标。
触发特效区域：特效名称、触发类型、触发特效与概率。
开战名称保存在effectName，战斗过程中触发的名称保存在triggerEffectName，两者独立；旧数据未包含triggerEffectName时默认为空。
触发特效：无特效、增幅、真伤、立即执行下次行动、debuff、buff。
概率填写百分数（0～100）；未启用的矩阵行记录零系数；隐藏的特效不保存。
debuff包括流血、瘟疫、灼烧、减速、眩晕。buff包括力量、魔力、技巧、速度、护甲、抗性提升。
buff/debuff最大层数为1～999整数。增幅和buff使用四行六属性转化矩阵。
真伤记录力量、魔力、技巧、速度和武威系数。

当前仅保存定义，尚不执行装备增幅或触发，也尚未将装备库绑定角色配装选择。
开战系数的取值时机、叠加规则、概率互斥、立即行动间隔、真伤结算等需后续确定。
“开始buff对象”的单个队友选项记录作用范围，具体选择哪个队友需在队伍配置阶段确定。

| 方法 | 路径 | 功能 |
| --- | --- | --- |
| GET | /api/equipment | 获取装备库 |
| GET | /api/equipment/{id} | 获取装备 |
| POST | /api/equipment | 创建装备，空ID时生成 |
| PUT | /api/equipment/{id} | 更新装备 |
| POST | /api/equipment/import | 合并导入 |

创建、修改请求体是单个装备对象；导入格式：{"schemaVersion":1,"equipment":[...]}。
记录格式可在表单“查看装备数据”及/docs中查看。错误返回{"error":"原因"}。
重复创建ID和导入冲突返回409；错误数据不写入；已有文件损坏时拒绝覆盖。

验证命令：项目虚拟环境运行python tests/verify_equipment_api.py；有Node时可运行node tests/verify_equipment_editor.cjs进行表单逻辑检查（不替代浏览器外观验证）。

旧装备数据中的转职名称在读取、导入或保存时归并到对应大类；技能职业仍选择具体转职。

战斗开始增幅和触发特效各有独立开关，新装备默认关闭。关闭会隐藏并禁用对应输入，保留配置便于重新打开；startingBuff.enabled和triggerEnabled记录是否生效。旧装备依据已有开战配置及触发特效恢复启用状态。

触发特效的增幅转化矩阵增加已损失血量系数lostHitPoint（最大血量减当前血量）；旧数据缺少该项时默认0。此项目前保存为定义，待战斗引擎接入时参与计算。

触发特效支持多条（最多50条）。点击添加特效，分别选择各条名称、触发类型、概率与效果；点击特效编号切换编辑，可删除当前特效。所有条目随装备一起保存，使用triggerEffects数组，每项为{name,triggerType,probability,effect}。旧单条字段兼容读取为第一条，后续引擎应遍历triggerEffects。当前仍只保存定义。
