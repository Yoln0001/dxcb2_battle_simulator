# TAS 战斗播放器

顶部「TAS 战斗」使用当前队伍配置新建独立战斗，时间精度为 0.1 秒。Boss 配置了技能组时自动执行 Boss 攻击；没有技能组时明确提示本场没有 Boss 攻击。原单次和批量模拟入口保持独立。

每个角色可以切换手动和自动。手动时，轮到冷却已结束且未眩晕的角色结算行动，播放器暂停，显示实时血量、属性、增幅和负面状态。可选择当前转职技能库中的技能，或「本次等待 0.1 秒」。单体治疗可以指定存活队友；群体治疗和 buff 按技能本身配置。选择后仍保持暂停，需要点击播放继续推进；同刻其他手动角色会按结算顺序继续请求选择。自动模式沿原技能组的当前节点继续执行，需要先配置技能组。

回溯滑块仅允许进入已经探索的时间，后退按钮回退 0.1 秒，指令记录按钮回到该指令前一格。通过固定随机种子和操作日志重放恢复真实状态，包括 Boss 图节点、冷却、装备触发、DOT 和随机数状态。回溯本身保留历史；回溯后施法、推进或切换模式会替换后续历史。一个时间点可处于结算中途，此时 UI 明确提示等待角色选技能。

会话仅保存在当前后端进程内存中，空闲一小时失效，关闭播放器会释放会话；不写入人物、装备、技能等库文件。本版不包含操作脚本的导入、导出或跨后端重启保存。

## 接口

- `POST /api/battle/tas`：队伍配置创建会话，返回 id、seed、revision、实时快照、可选技能、当前待选择角色和探索范围。
- `POST /api/battle/tas/{id}`：携带最新 revision，kind 为 step、cast、hold、mode 或 seek。cast 指定 character、skill_id，可选 target_character 指定单体治疗目标；mode 指定 character、mode（manual/auto）；seek 指定整数 tick（0.1 秒单位）。
- `DELETE /api/battle/tas/{id}`：释放会话。

旧 revision 返回 409；不存在或过期会话返回 404；提前施法、选错转职技能、无技能组切换自动、回溯未探索时间等返回 400。

## 验证

`tests/verify_tas.py` 检查全自动与原 Boss 战斗逐事件完全一致、手动冷却和治疗、有限技能组之后继续手动、无技能组手动、眩晕、等待、回溯和分支。

`tests/verify_tas_api.py` 使用临时库启动真实 HTTP 服务，检查创建、推进、施法、回溯、冲突和关闭。

`tests/verify_tas_ui.cjs` 检查播放器按钮、自动暂停、目标选择、模式切换和滑块接线。此项为 DOM 交互测试，不代替真实浏览器视觉检查。
