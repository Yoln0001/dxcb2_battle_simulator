# 批量模拟

在主界面设置战斗时长、模拟次数和完整队伍配置，点击“开始批量模拟”。运行时显示已完成次数及实际计算用时。

结果依次展示：总战斗次数、达标次数、通过率、模拟用时；期望、最高和最低伤害；1%、5%、10%及自定义分位数；四名角色的期望伤害；每名角色各装备触发特效的平均次数。

达标定义为在设置时间内令目标生命值归零，通过率=达标次数/总次数×100%。期望伤害是所有场次伤害的算术均值，包括未达标场次。角色伤害包含其技能、装备、持续伤害和携带的契约伤害。特效均值的分母为全部模拟次数，零次触发的场次也参与平均，战斗开始增幅不算行动触发次数。

分位数从高伤害到低伤害排序（0%为最高，100%为最低），位置为(n-1)×百分比/100，相邻样本线性插值。结果中的自定义分位数可即时修改，不需要重跑。模拟用时为实际计算耗时，单位秒，不是游戏中的战斗时长。

POST /api/battle/simulate-batch 启动任务，GET /api/battle/batch/{job_id} 查询进度及结果。场次超过 10 万时，查询结果不再回传完整伤害列表（标记 sorted_damage_omitted），自定义分位数改由 GET /api/battle/batch/{job_id}/percentile?percent=… 用服务端保存的同一份数据精确计算，算法与结果中的各分位数相同。所选 Boss 设置了技能组（有入口且有子组）时，模拟自动包含 Boss 攻击；没有技能组时 Boss 只作为受击目标，按普通模拟计算，速度不受影响。返回结果中的 boss_attacks 标明本次实际采用的模式。旧路径 /api/battle/simulate-batch-with-boss 保留为别名，行为相同。后台任务只保存在服务内存中，服务重启将清除任务。同一服务每次执行一个批量任务。批量复用单次模拟规则，但不生成逐场时间表、最好或最坏场次详情。


批量加速：缓存由上次行动时间、技能冷却、力量、卸负和速度共同决定的冷却截止时间；任一输入变化自动重新计算。批量模式只跳过确定没有事件的0.1秒时间步，行动、到期、献祭、灼烧和契约仍在原0.1秒网格结算。单次时间表继续逐步推进。相同随机种子下快速与参考模式的达标、伤害和特效计数应一致。基准配置20场由约2.27秒降到0.70秒，约3.2倍，仅代表该配置和机器。

进一步加速：buff 和献祭结算只复制会修改的运行状态，不再深度复制整支队伍及历史记录。500 场及以上自动使用多进程，默认最多 8 个进程，小批次继续单进程以避免启动开销。每场随机种子及结果汇总顺序保持一致。

性能基准：tests/benchmark_batch.py 的 200 秒、四角色、回血、技巧 buff 覆盖、灼烧和契约配置，1000 场串行约 13.75 秒、8 进程约 4.53 秒；10000 场约 31.91 秒，包含进程启动用时。该基准通过率为 0%，另外 verify_parallel_batch.py 使用包含成功与失败场次的配置验证串行和并行统计完全一致。具体耗时取决于设备、战斗配置和后台负载，尚未达到一万场 4 秒。


Numba 批量核心（默认）：engine/runtime/compiled 将每个角色的属性、装备、技能、buff 和技能组节点转为数值数组；整个战斗循环使用 njit 编译，独立场次使用 prange 多线程，不再产生逐时刻日志或 Python 状态对象。保留 0.1 秒时间网格、四角色连续行动块、随机同刻排序、动态冷却、装备首个触发、临时增幅、伤害后装备 buff、覆盖/层数、回复对象、死亡、灼烧、契约及条件跳转规则。单次模拟继续使用原 Python 时间表引擎。

首次运行需要加载/编译内核，启用 cache=True，耗时包含在模拟用时中，结果另列内核加载/编译用时。之后技能或装备的数值变化无需重编译。取消信号在小批次间检查；正在编译时须等编译完成再退出。不支持的配置或缺少 Numba 时回退 Python，并在结果中说明。

编译核心使用与 CPython random.Random 相容的 MT19937 和 shuffle，沿用每场种子。对照覆盖 30 场复杂战斗、60 场动态冷却/负冷却/立即行动/死亡、100 场当前装备技能库组合，以及 200 场成功和失败混合的批量；通过次数和触发次数一致，伤害按浮点误差容限验证。

实测：使用现有装备/技能/技能组库组合的测试队伍（不是浏览器中保存的完整队伍），200 场 Python 单进程约 6.94 秒，njit 约 0.22 秒；内核缓存就绪后 10000 场约 1.61 秒、100000 场约 16.04 秒。实际速度依赖队伍、时长和机器。复现脚本：tests/benchmark_compiled_batch.py，仅读取库文件，不修改保存数据。
